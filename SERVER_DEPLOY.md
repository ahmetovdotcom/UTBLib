# Развёртывание рядом с действующим сайтом

Новый проект: `kaztbu-catalog-v2`. Собственные контейнеры, сеть и том PostgreSQL.
Публикуется только порт 8097. Порты 80/443, файлы и база действующего сайта не используются.
Не запускайте `down -v`, `docker system prune --volumes` или команды очистки базы.
Нужны Linux, Docker Engine с Compose v2, доступ к Docker Hub/npm/PyPI при сборке и свободное место.
Сборка выполняется на сервере под его архитектуру (amd64/arm64), образы с Mac не требуются.
Начальный ориентир ресурсов: 2 CPU, 4 ГБ свободной RAM; проверьте запас ресурсов рядом со старым сайтом.

## 1. Клонировать репозиторий

```sh
git clone git@github.com:ahmetovdotcom/UTBLib.git
cd UTBLib
./deploy/init.sh
```

Это основной способ установки. На сервере нужен SSH-ключ с доступом к репозиторию.
Далее выберите вариант Б для новой базы с актуальным импортом MARCSQL.

### Альтернатива: архив исходников

На Mac замените USER и SERVER своими значениями:

```sh
scp library-catalog-server-2026-10-21.tar.gz USER@SERVER:~/
```

На сервере:

```sh
mkdir -p ~/library-catalog-v2
tar -xzf ~/library-catalog-server-2026-10-21.tar.gz -C ~/library-catalog-v2 --strip-components=1
cd ~/library-catalog-v2
./deploy/init.sh
```

Скрипт создаёт `.env.server` со случайными паролями. Повторный запуск не меняет их.
Файлы с реальными паролями и API-ключами из разработки в архив не включены.
Логин: `admin`; пароль первой установки смотрите в `ADMIN_INITIAL_PASSWORD` файла `.env.server`.
Google Books: при необходимости задайте свой `GOOGLE_BOOKS_API_KEY` в этом же файле.

Сначала проверьте, свободен ли порт:

```sh
ss -ltn | grep ':8097 ' || true
docker ps --format 'table {{.Names}}\t{{.Ports}}'
```

Если занят, измените `WEB_PORT` в `.env.server`. Используйте новый порт также в туннеле/прокси.

## 2. Выбрать, какие данные переносим

**Для выбранного запуска через Git и актуального MARCSQL используйте вариант Б.**
При необходимости можно перенести текущую базу приложения (вариант А). В ней уже есть исправления сотрудников,
настройки, пользователи, справочники, экземпляры и история. Свежий импорт только из MARCSQL
эти локальные изменения и настройки не перенесёт.

### Вариант А: сохранить всю текущую работу

Если нужна полная копия существующей установки, получите dump у её администратора.
Файл `library-catalog-current-2026-10-21.dump` в Git не включён.
Это приватная копия базы приложения: передавайте её только на свой сервер.
Скопируйте dump через scp. Следующие команды выполняются **до первого запуска API**, только в новом пустом проекте:

```sh
./deploy/compose.sh up -d --wait db
./deploy/compose.sh exec -T db psql -U catalog -d catalog -Atc "select count(*) from information_schema.tables where table_schema='public';"
```

Должно быть **0**. Если не 0 — остановитесь: это уже не пустая база; не используйте `--clean`.
При нуле восстановите копию (путь уточните по месту загрузки):

```sh
./deploy/compose.sh exec -T db pg_restore -U catalog -d catalog --no-owner --no-acl --exit-on-error < ~/library-catalog-current-2026-10-21.dump
./deploy/compose.sh up -d --build --wait
```

Сохранятся существующие пользователи и пароли. `ADMIN_INITIAL_PASSWORD` не сбрасывает пароль
администратора из копии. Перед доступом сотрудников смените прежний простой пароль через меню аккаунта.
После восстановления повторный импорт для переноса уже имеющихся данных не нужен.
Копия сделана в момент упаковки: более поздние изменения на Mac в неё не входят.
Перед окончательным переходом остановите редактирование на Mac и сделайте свежую копию.

### Вариант Б: новая пустая установка и импорт из MARCSQL

```sh
./deploy/compose.sh up -d --build --wait
```

Ниже описан импорт. Этот вариант не переносит сотрудников и локальные правки из старого приложения.

## 3. Открыть приложение, пока нет поддомена

По умолчанию 8097 привязан к localhost сервера. На Mac откройте SSH-туннель:

```sh
ssh -N -L 8097:127.0.0.1:8097 USER@SERVER
```

Пока команда работает, приложение доступно на `http://localhost:8097` вашего Mac.
Действующий `https://elibrary.kaztbu.edu.kz` работает как прежде.

Для временного доступа сотрудников **в доверенной локальной сети** можно вместо туннеля
задать `WEB_BIND=ЛОКАЛЬНЫЙ_IP_СЕРВЕРА` в `.env.server` и выполнить:

```sh
./deploy/compose.sh up -d web
```

Адрес: `http://ЛОКАЛЬНЫЙ_IP_СЕРВЕРА:8097`. Уточните доступ через сетевой экран у администратора сети.
Для публичного доступа используйте HTTPS на отдельном поддомене, не передавайте логины через публичный HTTP.

## 4. Постоянный адрес рядом со старым сайтом

Рекомендуемый адрес: **catalog.kaztbu.edu.kz**. Это отдельный поддомен, не подкаталог `/catalog`.
Сейчас приложение рассчитано на корень сайта; размещение в подкаталоге потребует дополнительных изменений.

Администратор домена/сервера должен:
1. Направить DNS нового имени на этот сервер.
2. Добавить отдельный виртуальный хост в текущий Nginx/Apache/панель, проксирующий запросы на `127.0.0.1:8097`.
3. Выпустить сертификат нового имени, проверить конфигурацию и применить reload.
4. Установить `COOKIE_SECURE=true`, оставить `WEB_BIND=127.0.0.1` в `.env.server` и выполнить `./deploy/compose.sh up -d api web`.

Шаблон для Nginx на хосте: `deploy/nginx-subdomain.conf.example`. Он не применяется автоматически.
Не заменяйте конфигурацию elibrary и не запускайте второй процесс на занятых 80/443.
Если текущий прокси в Docker, 127.0.0.1 внутри его контейнера — не хост; администратор должен
настроить маршрут к новому приложению через доступный адрес/отдельную общую сеть.

## 5. Импорт каталога и экземпляров — источник только для чтения

Сервер должен видеть `10.0.1.16:1433` через локальную сеть или VPN.
Не публикуйте SQL Server в Интернет. Контейнер импортёра выполняет в источнике только SELECT.
Желательно использовать SQL-пользователя с правами чтения `DOC`, `INV`, `SIGLAS`.
Ассистент к MARCSQL не подключался; команду запускаете вы.

Откройте `.env.marcsql`, созданный init, и заполните:

```dotenv
MARCSQL_HOST=10.0.1.16
MARCSQL_PORT=1433
MARCSQL_DATABASE=marc
MARCSQL_USER=marc
MARCSQL_PASSWORD=ваш_пароль
MARCSQL_SOURCE=marcsql-main
```

Не меняйте `MARCSQL_SOURCE` между повторами: он участвует в защите от дублей.
Перед импортом сделайте резервную копию целевой базы:

```sh
./deploy/backup.sh
./deploy/import-all.sh --apply
```

Последняя команда сама определяет ID типов документов в целевом приложении (создаёт недостающие
«Коллекция» и «Сериальное издание»), собирает импортёр, импортирует сначала каталог, затем экземпляры.
Ничего не очищает. Повторный запуск использует исходные DOC_ID/INV_ID и не должен создавать дубли.
Изменившиеся исходные записи/конфликты выводятся в отчёт, а не молча перезаписывают локальные правки.
При ошибках каталога этап экземпляров не запускается: устраните причину и повторите команду.

Экземпляры загружаются как имеющийся фонд, без создания фиктивных поступлений и оборотов КСУ.
Списанные и неподходящие строки пропускаются по действующим правилам импортёра; конфликты номеров
не скрываются. Итог может быть меньше числа строк INV — обязательно проверьте отчёт.
Отчёты накапливаются в томе `import_reports`:

```sh
./deploy/compose.sh run --rm --no-deps importer python -m app.import_marcsql --show-report --report /import/reimport-catalog.jsonl
./deploy/compose.sh run --rm --no-deps importer python -m app.import_marcsql_copies --show-report --report /import/reimport-copies.jsonl
```

Если каталог уже импортирован, можно отдельно повторить экземпляры:

```sh
./deploy/compose.sh run --rm --no-deps importer python -m app.import_marcsql_copies --apply --limit 0 --report /import/reimport-copies.jsonl
```

## 6. Проверка и обслуживание

```sh
./deploy/compose.sh ps
curl -f http://127.0.0.1:8097/api/health
./deploy/compose.sh logs --tail=100 api web
./deploy/backup.sh
```

Бэкапы хранятся в `backups/`; копируйте их на другое устройство. Отдельно сохраняйте `.env.server`.
Для обновления: бэкап, новые исходники (не затирать `.env.server` / `.env.marcsql`),
`./deploy/compose.sh up -d --build --wait`. Миграции выполняются автоматически.
Для остановки только этого проекта: `./deploy/compose.sh stop`. Не удаляйте тома базы.

Проверено по документации Docker:
- https://docs.docker.com/compose/how-tos/project-name/
- https://docs.docker.com/engine/network/port-publishing/
