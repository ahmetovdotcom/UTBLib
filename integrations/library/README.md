# Готовый студенческий сайт library + данные UTBLib

Согласованная схема: `library` остаётся отдельным Laravel-сайтом со своими готовыми
страницами. Поиск и карточка книги получают библиографию и наличие из UTBLib через
серверный API. Интерфейс сотрудников UTBLib остаётся на прежнем адресе.

```text
Браузер → готовые страницы /catalog и /book/... в library
        → Laravel CatalogReadService / BookDetailReadService
        → GET UTBLib /api/public/v1/...
        → существующие записи, экземпляры, выдачи и брони UTBLib
```

## Что подключено

- Каталог, карточка книги, поиск по заглавию, авторам, ISBN, УДК, издателю и тематике.
- Язык, годы, тип документа, категория, пункт выдачи, наличие, сортировка, страницы.
- Все каталожные записи, включая записи без экземпляров. Число записей и число
  физических экземпляров не смешиваются.
- Наличие из живых таблиц: занятые, забронированные, ремонтируемые и ограниченные
  экземпляры не считаются доступными для выдачи на дом. Списанные исключены.
- Библиография остаётся на языке записи. Подписи интерфейса локализует готовый сайт.
- Подборки готового сайта сохраняют отдельные идентификаторы `utblib-N`.

Это интеграция чтения каталога. Личные кабинеты, учёт выдач и бронирование между
двумя системами не синхронизируются. Для записей UTBLib старое бронирование выключено.
Ресурсы, репозиторий, новости и события, а также их блоки на главной подключаются
отдельным флагом `UTBLIB_CONTENT_ENABLED=true`. Управление — UTBLib → Сайт.
Подробности и ограничения доступа к файлам: [SITE_CONTENT.md](../../SITE_CONTENT.md).
Файлы книг, обложки и произвольные MARC-ссылки пока не публикуются: существующий
UTBLib не хранит отдельного разрешения на их публичное распространение. Фондовые и
академические идентификаторы старой базы не сопоставляются автоматически; фильтры
старых коллекций без соответствий возвращают пустой результат. Для фильтра филиала
используются реальные коды пунктов выдачи UTBLib.

## Установка адаптера

Локальная проверка (после установки адаптера в локальный `library`):

```bash
sh integrations/library/run-local.sh /path/to/library
```

Открыть `http://127.0.0.1:8098/catalog?lang=ru`. UTBLib должен работать на 8096.
Переменные передаются только процессу предпросмотра, `.env` сайта не изменяется.

Сначала обновить API UTBLib обычным способом с сохранением его Compose overlays.
Каталожный мост не требует миграций. Раздел «Сайт» требует миграции
`0017_site_content` (выполняется при старте API) и пересборки API и staff-фронтенда.
Перед обновлением сохраните резервную копию.

Из корня UTBLib:

```bash
python3 integrations/library/install.py /home/admtutor/projects/library --check
python3 integrations/library/install.py /home/admtutor/projects/library
```

Установщик добавляет адаптер, конфигурацию и тесты, регистрирует один provider и
точечно меняет источники данных маршрутов, статистики и идентификаторы ссылок. Дизайн и
существующие сервисы не заменяет. При неожиданном содержимом файлов останавливается
до записи. Повторная установка допустима; чужие изменения файлов адаптера не затираются.
Рекомендуется сохранить изменения в собственном Git-репозитории `library`.

В приватном `.env` **сайта library**, не UTBLib:

```dotenv
UTBLIB_CATALOG_ENABLED=true
UTBLIB_CONTENT_ENABLED=true
UTBLIB_CATALOG_URL=https://libstaff.kaztbu.edu.kz
UTBLIB_CATALOG_TIMEOUT=10
```

URL — корень UTBLib без `/api`. Он должен быть доступен именно PHP-контейнеру
`library`. На одном сервере можно использовать адрес web-контейнера UTBLib в общей
Docker-сети. `127.0.0.1:8097` внутри контейнера library не является адресом хоста.
Проверку TLS не отключать. Ключ OpenAI, ADMIN_KEY и пароль сотрудника не нужны.

После изменения `.env` (для подтверждённого ранее контейнера `library-app-1`):

```bash
docker exec library-app-1 php artisan config:clear
docker exec library-app-1 php artisan view:clear
docker exec library-app-1 php artisan route:clear
```

Если переменные задаются окружением Compose, а не Laravel-файлом `.env`, пересоздать
только сервис приложения со всеми его действующими настройками. Не удалять тома.

Проверить `/catalog`, `/resources`, `/repository`, `/news`, `/events`, главную и карточку книги на старом сайте. Серверный тест адреса:

```bash
docker exec library-app-1 php artisan tinker --execute='dump(app(\App\Services\Library\CatalogReadService::class)->search(limit: 1)["meta"]);'
```

Отключение: `UTBLIB_CATALOG_ENABLED=false`, `UTBLIB_CONTENT_ENABLED=false`, затем
`config:clear` и `route:clear`. Старый каталог и
его БД не переписываются. При включённой интеграции и недоступности UTBLib сайт
возвращает 503, а не подменяет результат данными старого каталога.

## Контракт и защита данных

- `GET /api/public/v1/catalog` → `{data, meta}`; limit 1–100, page от 1.
- `GET /api/public/v1/books/utblib-N` → `{data, success}` или 404.
- ISBN допустим как ссылка для совместимости; при совпадениях выбирается запись с
  наименьшим ID. Ссылки нового каталога всегда используют `utblib-N`.
- `GET /api/public/v1/facets` → значения фильтров и границы годов.

API намеренно общедоступен и только для чтения. Браузер обращается к своему сайту,
поэтому CORS и передача ключей в JavaScript не нужны. Выдаются только явно выбранные
поля MARC и агрегаты экземпляров. Нет полного MARC, операторов, накладных, цен,
инвентарных номеров, внутренних примечаний, читателей или сроков чужих выдач.
Поиск также не использует внутренний `search_text`. Метаданные кэшируются по
существующим версиям записей; наличие вычисляется заново при каждом запросе.

## Проверки

UTBLib: `backend/tests/test_public_catalog.py`, `test_security.py`, `test_circulation.py`.
Адаптер: после установки `php vendor/bin/phpunit tests/Feature/UTBLibCatalogTest.php`.
Тесты Laravel используют изолированную SQLite, не рабочую БД. Проверяются исходные
Blade-страницы, фильтры, отсутствие записи данных, недоступный API и границы ID.

Контент: `backend/tests/test_site_content.py` и `tests/Feature/UTBLibContentTest.php`.
Проверяются публикация, расписание, отзыв файлов, CSRF/права, исходные шаблоны,
языковой fallback, ссылки и отсутствие обращения к старым ID.
