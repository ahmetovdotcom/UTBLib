# Контент готового сайта library

UTBLib управляет данными, отдельный Laravel `library` показывает их своими прежними
Blade-страницами. Не переносить публичный frontend в staff-приложение.

## Работа сотрудника

В UTBLib откройте **Сайт → Ресурсы / Репозиторий / Новости / События**. Администратору
раздел доступен сразу; другим сотрудникам назначается право `site.manage`.

- Добавьте название хотя бы на одном языке, адрес страницы латиницей и описание.
- Переводы ru/kk/en необязательны; если перевода нет, показывается имеющийся текст.
- Сохраните черновик, прикрепите изображение (JPEG/PNG/WebP, 8 МБ, до 25 Мп) и,
  для репозитория, PDF до 25 МБ. Файлы можно просмотреть и убрать.
- Выберите «Опубликовано» и сохраните. Будущая дата откладывает показ автоматически,
  отдельный планировщик для этого не нужен. «Черновик» и «Архив» скрывают страницу и файлы.
- Для события задайте начало, при необходимости окончание, место, организатора,
  ссылки на регистрацию и трансляцию. В списке ближайших событий прошлые не показываются;
  опубликованная страница прошедшего события остаётся доступной.
- Для ресурса задаются ссылка, поставщик, категория, типы содержимого, условия доступа
  и окончание срока. Ограничения кампуса / входа проверяет готовый сайт перед переходом.
- Для репозитория есть авторы, вид работы, язык, год, факультет, кафедра, специальность,
  руководитель, УДК, DOI, источник, правообладатель и лицензия. PDF закрыт по умолчанию.
  Можно открыть его всем или оставить только описание; дата эмбарго задерживает открытие.

«Показывать на главной» управляет блоком новостей. Репозиторий на главной показывает
последние опубликованные работы. Снятие с публикации сохраняет запись и журнал изменений.
Сохранение версии, изменённой другим сотрудником, возвращает конфликт и не затирает правки.

## Устройство и развёртывание

- `backend/app/site_content.py`: модели, валидация, staff CRUD, upload/preview и public API.
- `backend/migrations/versions/0017_site_content.py`: только три новые таблицы.
- `frontend/src/SiteContentPage.vue`: кабинет сотрудника. Корень UTBLib остаётся staff UI.
- `integrations/library/`: opt-in адаптер готового сайта. Установщик сохраняет внешний вид
  и существующие изменения, проверяет ожидаемый контекст до записи.

Файлы хранятся в `site_assets.content` в БД, без отдельного тома. Обычный `deploy/backup.sh`
сохраняет их вместе с метаданными. Изображения перекодируются без исходных EXIF.
Публичные ответы не содержат авторов служебных действий, внутренних версий или аудита.
Текст редактируется как обычный текст; шаблоны экранируют HTML.

`GET /api/public/v1/content/{resources|repository|news|events}` — список, страницы по 100.
`GET /api/public/v1/content/{kind}/{slug|utblib-ID}` — карточка опубликованного материала.
`GET /api/public/v1/content-assets/{id}/{image|pdf}` — повторная проверка публикации и доступа.
Браузер получает файл через `/utblib-content/assets/...` на домене library; внутренний
адрес UTBLib ему не нужен. Файлы не кэшируются, поэтому отзыв проверяется при каждом запросе.

Инструкция установки: [integrations/library/README.md](integrations/library/README.md).
Для разделов нужен `UTBLIB_CONTENT_ENABLED=true` в окружении **library**, а также
`UTBLIB_CATALOG_URL` с доступным PHP-контейнеру корнем UTBLib. После изменения флагов
очистить Laravel config, route и view cache. Для PDF на внешнем прокси libstaff установить
`client_max_body_size 26m;` (образец в deploy обновлён); внутренний web уже настроен.
Не заменять рабочий Nginx-конфиг целиком. Перед локальной миграцией сохранена копия БД.

## Границы

Старые таблицы library не изменяются и не становятся зеркалом новой БД. В локальном
образце четыре таблицы контента пусты, поэтому автоматического импорта старых публикаций
нет. Если на production они заполнены, их нужно отдельно перенести с сохранением прав
на публикацию **до** переключения флага; установка не объявляет старые закрытые файлы публичными.

Модерация прежней админки, её аналитика кликов, персональные кабинеты и читательская
авторизация между системами не перенесены. Для PDF в новой админке доступны «всем» и
«только описание»; политика «только вошедшим читателям» не включается автоматически.
Блок старых «трудов преподавателей» не подменяется несопоставленными записями старой базы.
Произвольные MARC-вложения книг по-прежнему не публикуются через CMS репозитория.

Если upstream недоступен, страницы возвращают 503, а не старые или демонстрационные записи.
Развёртывание этой версии на production и включение флага на действующем сайте — отдельный шаг.
