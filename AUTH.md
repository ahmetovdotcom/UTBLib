# Пользователи, роли и права

Вход в приложение: логин и пароль. Администратор управляет сотрудниками во вкладке
«Пользователи и права». Можно создать пользователя, изменить имя/логин, назначить
роль и права, задать новый пароль или заблокировать вход. Кнопка «Удалить» удаляет пользователя из рабочего списка и отзывает доступ.
Запись остаётся в базе с признаком удаления для сохранения истории действий.
Восстановление через интерфейс недоступно, логин остаётся зарезервированным. Последнего активного администратора отключить или
понизить или удалить нельзя. Изменения защищены версией записи; параллельное управление
администраторами сериализуется в PostgreSQL.

Роли:
- Администратор: полный доступ, включая управление пользователями.
- Библиотекарь: начальный набор прав на каталог, экземпляры и поступления;
  администратор может изменить флажки для конкретного сотрудника.
- Наблюдатель: первоначально только чтение каталога и экземпляров; права также
  можно настроить. Роль и флажки показываются при редактировании сотрудника.

Каждому активному пользователю доступен просмотр каталога и экземпляров.
Остальные права: создание/редактирование записей, удаление записей, изменение
экземпляров, просмотр и изменение поступлений, отмена поступлений, просмотр
списаний, списание, настройка ввода/справочников, импорт MARCSQL. Только роль
администратора даёт доступ к управлению пользователями. Проверка выполняется на
сервере для каждого маршрута; скрытие кнопок — дополнительное удобство.

## Первое развёртывание

В `.env` задайте `ADMIN_INITIAL_PASSWORD` до первого запуска. Если таблица
пользователей пустая, создаётся `admin`; при следующих запусках пароль никогда не
перезаписывается. Можно убрать `ADMIN_INITIAL_PASSWORD` после успешной
инициализации. Для текущей локальной установки сохранён согласованный пароль
`admin`; изменить его можно кнопкой «Сменить пароль». Новые пароли через интерфейс
должны содержать не менее 8 символов. Начальный пароль для новой установки
рекомендуется задать более длинным.

`ADMIN_KEY` теперь служит только интеграционным ключом двух POST-маршрутов:
`/api/import/marcsql` и `/api/import/marcsql-copies`. Он не открывает каталог,
настройки или пользователей. В рабочей локальной установке прежний общий ключ
заменён случайным; compose.import.yaml читает актуальное значение из `.env`.
Команды импортёров не изменились. MARCSQL по-прежнему только для чтения.

## Сеансы и пароли

Пароли хешируются scrypt с индивидуальной случайной солью. Сервер хранит только
SHA-256 от случайного токена сеанса. Cookie — HttpOnly, SameSite=Strict, срок
сеанса 12 часов. При смене пароля, блокировке или изменении учётной записи все её
сеансы отзываются. Выход отзывает текущий сеанс. Редактирование собственной
учётной записи администратором также требует повторного входа.

Изменяющие запросы требуют X-CSRF-Token, выдаваемый после входа / через auth/me;
проверяется Origin при его наличии. После 10 неверных попыток входа по одному
логину вход блокируется на оставшуюся часть 15-минутного окна. Изменения учётных
записей записываются в user_audit без паролей/хешей. До 100 последних событий
доступно администратору через GET /api/users/audit.

В локальном HTTP-развёртывании `COOKIE_SECURE=false`. Для доступа через интернет
нужен HTTPS и `COOKIE_SECURE=true`, а обратный прокси должен передавать исходный
Host. Текущий Compose публикует только localhost:8096.

Отложенные операции в браузере изолированы по ID пользователя. Пароли и токены
сеансов не сохраняются в localStorage/sessionStorage. Старые отложенные операции,
созданные до перехода на пользователей, автоматически другому сотруднику не
передаются: при их наличии нужно отдельно сверить результат операции.

## API

POST /api/auth/login {username,password} -> user, csrf_token + cookie.
GET /api/auth/me -> текущий пользователь и csrf_token.
POST /api/auth/logout -> выход.
POST /api/auth/password {current_password,new_password} -> смена и выход.
GET /api/users -> список, словарь прав, наборы прав ролей (admin).
POST /api/users -> создание (admin).
PUT /api/users/{id} -> изменение с version (admin).
DELETE /api/users/{id}?version=N -> удаление с подтверждением актуальной версии (admin).

После завершения или отзыва сеанса возвращается 401, при недостатке прав — 403.
На неизвестные операции разрешение по умолчанию не выдаётся.

Ограничения: нет MFA, SSO, сброса пароля по электронной почте, организационных
групп и ограничений по филиалам. Встроенный журнал касается управления доступом;
полное авторство всех библиотечных операций потребует отдельного расширения.

Миграция 0008 добавляет только новые таблицы; существующие библиотечные таблицы
не меняются. Производственный откат — новой миграцией; downgrade откажет, если
пользователи уже существуют. Резервную копию следует сохранять перед обновлением.

В новых записях с локальным полем 097 $b оператор автоматически заполняется
из ФИО (display_name) вошедшего пользователя при открытии новой карточки.
Это начальное значение можно изменить или очистить; сервер сохраняет введённое значение. В существующих и импортированных записях оператор
не заменяется автоматически. Удаление пользователя не меняет имя в каталоге.
