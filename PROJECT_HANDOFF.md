## 9 ноября 2026: настоящее удаление экземпляров

Мягкое удаление оставляло инвентарный номер и штрихкод занятыми. Теперь DELETE
физически удаляет экземпляр из copies, CopyHistory переносится в отдельный
CopyDeletion (миграция 0021_copy_deletions), служебное CopyCirculation удаляется.
Номера можно использовать заново в любой карточке. Подтверждение в редакторе
называет действие «Удалить полностью». Ранее cancelled-экземпляры можно открыть
и очистить, повторно не уменьшая суммы поступления/КСУ. Для активного экземпляра
пересчитываются поступление и КСУ, пустое поступление отменяется.

Архив удаления не имеет FK на копию и не резервирует номера. Старый DELETE
идемпотентен и не затронет новую копию; старый запрос создания не воскресит
удалённую. GET истории поддерживает архив. MARCSQL source остаётся с copy_id=NULL,
чтобы импорт не восстановил ошибочную привязку; MARCSQL не изменяется. Экземпляры
со связанной историей выдач, закреплённых броней, штрафов/инцидентов или списания
защищены; эти операции не удаляются каскадом. Права copies.edit, CSRF, версии
и общий шлюз записи сохранены. SQLite использует AUTOINCREMENT для стабильных ID.

перестановка допустима, а клонирование старой повторяющейся группы не даёт нового допуска.
Настройки входят в существующий экспорт/импорт настроек; распознавание по фото тоже

При старте API выполняется alembic upgrade head. Существующие профили не следует затирать сидированием. Записи используют версии и конфликт 409 против потерянных изменений. Сеансовая авторизация: cookie + CSRF для изменений. ADMIN_KEY — интеграционный ключ, не пароль сотрудника.

## 5. MARCSQL: источник и повторный импорт

Источник Microsoft SQL Server: 10.0.1.16:1433, БД marc. Реквизиты только в приватной .env.marcsql.
DOC: DOC_ID, RECTYPE, BIBLEVEL, ITEM (ntext). ITEM — локальный MARC-подобный формат с управляющими разделителями; использовать существующий parser, не считать обычным CSV или готовым ISO2709.
Типы a/m, a/a, a/c, a/s должны сопоставляться реальным ID целевой установки; prepare_server_import.py определяет их, не хардкодить номера типов.

INV связан с DOC по DOC_ID; устойчивый идентификатор экземпляра — INV_ID. Сопоставления в текущем импортёре: T090e — инвентарный номер, T876p — штрихкод, T876c — цена, T090f/справочник SIGLAS — сигла, SOURCE — источник, NOTES — примечание. Остальные исходные данные архивируются. Числовые даты REGDATE/DATE1/OFFDATE не конвертировать наугад.
Не интерпретировать INV.STATE через справочник STATES выдач: это разные контексты. Правила отбора смотреть в prepare_row в marcsql_copies.py.

Исторические числа, НЕ актуальный остаток: каталог 9867; INV 51474; один завершённый запуск создал 51126, пропустил 4, ошибки 344 (причины не все устранены). Пользователь первоначально согласился пропустить несколько нестандартных/списанных строк. Это не разрешение скрыть любые новые ошибки.

Повторный импорт:

- MarcsqlSource: (source, doc_id); MarcsqlCopySource: (source, inv_id).

- Не пытаться восстанавливать удалённые связи или повторно создавать удалённые записи автоматически.

### КСУ и редактирование экземпляров — 05.11.2026

Миграция `0019_copy_ksu`: `copies.ksu_entry_id` — явная необязательная FK на КСУ (один экземпляр в одной КСУ); `copies.invoice`; КСУ теперь может существовать без `acquisition_id`, имеет собственные source/invoice/note и необязательную дату документа.
