## 4. Продуктовые договорённости

### Каталог и рабочий лист

- Каталогизация и классификация открывает каталог записей. Настройка ввода и справочник полей — вложенные пункты.
- В списке показывать только заглавие 245$a, без подзаголовка/продолжения. Вместо внутреннего номера — колонка УДК. Есть фильтр УДК, поиск по инвентарному номеру и штрихкоду.
- Открытие карточки и переход страницы списка прокручивают к началу. Назад/Далее есть также сверху.
- Поля и подполя настраиваются для каждого типа. Нельзя терять импортированные скрытые значения из-за изменения формы.
- 097$b «Оператор»: для новой карточки подставляется ФИО вошедшего сотрудника; справочник формируется из пользователей системы. При содержательном редактировании сервер записывает имя редактирующего сотрудника. Простое открытие/сохранение без содержательных изменений не должно приписывать работу другому.
- Для справочника каждого поля есть настройка разрешения редактировать выбранное значение. Автопополнение должно учитывать уже существующие записи, включая импортированные.
- «Каталогизация → Требует внимания» проверяет выбранные поля/подполя на отсутствие непустых значений и несоответствие текущему справочнику своего типа документа. Автопополнение отключает проверку принадлежности списку; только allow_edit не отключает её, но результат помечается как требующий проверки. Имена операторов — рекомендации, не закрытый справочник. Настройки фильтра сохраняются для текущего пользователя в sessionStorage; возврат из карточки пересчитывает список. Подробнее CATALOG_ATTENTION.md.
- 952$a — тип литературы для КСУ ВШ: термин хранится как значение, расшифровка как пояснение. Коды научных, учебных, художественных, методических изданий и носителей внесены по фото пользователя.
- ISBN-поиск: Open Library и Google Books, предварительный просмотр результатов и явная кнопка вставки. Не перезаписывать карточку без выбора человека. GOOGLE_BOOKS_API_KEY хранится на сервере; ключи из старого чата не повторять.
- Служебные 001/005/008 и даты 990 управляются существующей логикой. Не подменять исторические даты текущей датой при импорте.

### Экземпляры, поступления, списание

Запись каталога описывает издание; экземпляр — отдельная физическая книга. У одного издания много экземпляров, поступивших разными партиями.

- Новое поступление создаётся в отдельном разделе, может содержать несколько названий и создаёт экземпляры атомарно.
- В редактировании каталога создаётся отдельный экземпляр ИМЕЮЩЕГОСЯ ФОНДА, без поступления/накладной; он не относится к новым поступлениям КСУ.
- Сохранение MARC, включая 541$n «Количество, объём», не создаёт экземпляры повторно и вообще не является счётчиком фонда. Это итоговая договорённость, заменившая раннюю идею автоматического создания по этому полю.
- Номер накладной не уникален и не служит ключом идемпотентности. Повторы защищаются UUID запроса/хешем, транзакциями и ограничениями БД.
- Экземпляр хранит инвентарный номер, штрихкод, сиглу, цену, известную дату/источник поступления, проверку и примечание. Денежные значения — Decimal; неизвестная цена не равна нулю. Идентификаторы — строки, ведущие нули штрихкода сохраняются.
- Поступления можно исправлять с историей. «Удаление» ошибочного поступления — отмена с сохранением истории.
- Списание в отдельной вкладке по инвентарному номеру. Списанные экземпляры сохраняются со статусом, а не физически удаляются.
- Каталожную запись с экземплярами/историей поступлений удалять запрещено.
- Бланки экземпляров печатаются из каталога, содержат индивидуальный инвентарный номер, классификацию, автора, заглавие, год, цену. Пользователь ориентировался на размер около 4×10 см и несколько бланков на A4; сверяй реальные настройки CopyForms, не ломай физические размеры общим CSS.

## 5. MARCSQL: источник и повторный импорт

Источник Microsoft SQL Server: 10.0.1.16:1433, БД marc. Реквизиты только в приватной .env.marcsql.
DOC: DOC_ID, RECTYPE, BIBLEVEL, ITEM (ntext). ITEM — локальный MARC-подобный формат с управляющими разделителями; использовать существующий parser, не считать обычным CSV или готовым ISO2709.
Типы a/m, a/a, a/c, a/s должны сопоставляться реальным ID целевой установки; prepare_server_import.py определяет их, не хардкодить номера типов.

INV связан с DOC по DOC_ID; устойчивый идентификатор экземпляра — INV_ID. Сопоставления в текущем импортёре: T090e — инвентарный номер, T876p — штрихкод, T876c — цена, T090f/справочник SIGLAS — сигла, SOURCE — источник, NOTES — примечание. Остальные исходные данные архивируются. Числовые даты REGDATE/DATE1/OFFDATE не конвертировать наугад.
Не интерпретировать INV.STATE через справочник STATES выдач: это разные контексты. Правила отбора смотреть в prepare_row в marcsql_copies.py.

Исторические числа, НЕ актуальный остаток: каталог 9867; INV 51474; один завершённый запуск создал 51126, пропустил 4, ошибки 344 (причины не все устранены). Пользователь первоначально согласился пропустить несколько нестандартных/списанных строк. Это не разрешение скрыть любые новые ошибки.

Повторный импорт:

- MarcsqlSource: (source, doc_id); MarcsqlCopySource: (source, inv_id).
- Не менять MARCSQL_SOURCE: это часть идентичности источника.
- Новое добавляется. Уже известное с прежней контрольной суммой пропускается.
- Изменённое в старой базе выдаёт конфликт; существующее в UTBLib не перезаписывается.
- Конфликт инвентарного номера/штрихкода не создаёт второй экземпляр и не перезаписывает первый.
- Не пытаться восстанавливать удалённые связи или повторно создавать удалённые записи автоматически.
- Для вручную созданного издания без связи с MARCSQL автоматическое распознавание «той же книги» по названию/ISBN не гарантировано. Идемпотентность относится к исходным идентификаторам.

Последнее поручение владельца: «то что было изменено в нашей программе пусть так и остается. добавь только новые». Под это код обновления существующих записей НЕ добавлялся. Пользователю даны команды ниже; подтверждения их последнего запуска пока нет.

На сервере:

```sh
cd ~/projects/UTBLib
./deploy/backup.sh
./deploy/import-all.sh --apply
```

import-all.sh собирает importer, определяет типы, запускает каталог и затем экземпляры. При ошибках каталога Python завершает этап с кодом 1, и экземпляры НЕ запускаются. Каталог обрабатывает строки и сохраняет успешные добавления до финального сообщения об ошибках.
После проверки отчёта для отдельного запуска экземпляров:

```sh
./deploy/compose.sh run --rm --no-deps importer python -m app.import_marcsql_copies --apply --limit 0 --report /import/add-new-copies.jsonl
```

Отчёты в томе import_reports, путь /import внутри контейнера. Показать каталог:


## Дополнение 23.10.2026: поступления по специальностям

Второй отчёт КСУ: вкладка «Поступления по специальностям». Полные значения 952$j формируют колонки автоматически, без справочника сокращений. Период задаётся датами поступления включительно. В каждой колонке — разные record_id внутри партии, экземпляры и сумма строк поступления в KZT. Общий итог наименований — сумма по партиям.

Повторяющиеся одинаковые значения 952$j учитываются один раз. Пустая специальность и несколько разных специальностей получают отдельные колонки «Не указана специальность» и «Несколько специальностей — не распределено». Распределение между несколькими специальностями не угадывается, все книги и суммы учитываются ровно один раз. Пояснения содержат ссылки на исходные карточки.

Отменённые поступления и экземпляры без поступления исключены; проведённые поступления без номера КСУ показываются как «Без КСУ». Списания не уменьшают исторические поступления. Изменение каталога пересчитывает группировку. Неизвестная цена или валюта не KZT исключается из известной суммы с явным предупреждением и блокирует Excel; нераспределённые специальности допускаются в Excel с отдельными колонками и пояснениями. Доставка не включена.

API с правом ksu.view: GET /api/ksu/specialties/report и /api/ksu/specialties/export, параметры date_from/date_to. Код: ksu_specialties.py, KsuSpecialties.vue; тесты test_ksu_specialties.py. Миграция БД не требуется.

Последнее уточнение владельца: снова группировать только по «Специальности» (952$j). «Кафедра» (952$e) не используется даже при пустой специальности. Старые адреса /api/ksu/departments/report и /export оставлены как совместимые псевдонимы того же отчёта по специальностям.
