# UTBLib — библиотечная система

Каталогизация, экземпляры, поступления, списания, КСУ и статистика сотрудников.
Стек: FastAPI, Vue 3 / TypeScript, PostgreSQL, Docker Compose.

## Установка на Linux-сервере через Git

```sh
git clone git@github.com:ahmetovdotcom/UTBLib.git
cd UTBLib
./deploy/init.sh
./deploy/compose.sh up -d --build --wait
```

Для приватного репозитория SSH-ключ сервера должен иметь доступ к GitHub (например, deploy key только на чтение).
Логин первой установки — `admin`; случайный пароль находится в `ADMIN_INITIAL_PASSWORD` в `.env.server`.
Новый Docker-проект `kaztbu-catalog-v2` использует собственную базу и порт 8097, не занимает 80/443 текущего сайта.
По умолчанию порт доступен только на localhost сервера. Для первого открытия с компьютера:

```sh
ssh -N -L 8097:127.0.0.1:8097 USER@SERVER
```

Откройте http://localhost:8097. Для сотрудников настройте отдельный поддомен и HTTPS по [инструкции](SERVER_DEPLOY.md).

## Актуальные данные из MARCSQL

Заполните пароль и параметры подключения в `.env.marcsql` (создаётся при init), затем:

```sh
./deploy/import-all.sh --apply
```

Команда импортирует сначала каталог, затем экземпляры. MARCSQL используется **только для SELECT**.
Сервер должен видеть SQL Server `10.0.1.16:1433` через локальную сеть или VPN.
Карта типов определяется автоматически. Повторный запуск не очищает целевую базу; ошибки и пропуски фиксируются в отчётах.
Пользователи и локальные правки из другой установки UTBLib при импорте MARCSQL не переносятся.

## Обновление

```sh
./deploy/backup.sh
git pull --ff-only
./deploy/compose.sh up -d --build --wait
```

Не удаляйте том PostgreSQL. `.env.server`, `.env.marcsql`, пароли и бэкапы исключены из Git.
Подробности развёртывания, резервного копирования и отчётов: [SERVER_DEPLOY.md](SERVER_DEPLOY.md).

# Каталогизация и классификация — самостоятельный MVP

FastAPI + Vue 3 / TypeScript + PostgreSQL 17. Проект независим от QOR.

## Запуск

Требуются Docker Engine / Docker Desktop и Docker Compose v2.

```sh
cp .env.example .env
# Задайте POSTGRES_PASSWORD, случайный ADMIN_KEY для импорта
# и ADMIN_INITIAL_PASSWORD для первого входа администратора в .env.
docker compose -p standalone-library up -d --build
```

Откройте http://localhost:8096 и войдите как `admin` с паролем `ADMIN_INITIAL_PASSWORD`. В текущей локальной установке логин и пароль: `admin` / `admin`. Не заменяйте существующий `.env`. Пользователи и права настраиваются администратором в отдельной вкладке. [Подробности авторизации](AUTH.md). Порт доступен только на loopback; база данных не публикуется на хост.

При запуске API автоматически применяет миграции Alembic, затем идемпотентно создаёт типы «Книга» и «Научная статья». Записи по умолчанию не создаются. Изменённые типы сидирование не перезаписывает. Данные остаются в именованном томе PostgreSQL после `docker compose -p standalone-library down`. Команда `down -v` удаляет этот том.

## Работа с рабочим листом

Навигация слева: «Каталог записей», «Настройка ввода», «Справочник полей».

1. В «Настройке ввода» выберите тип документа или создайте свой. Справа ищите поля по русскому названию или коду и отмечайте нужные.
2. Слева задайте порядок стрелками ↑/↓, собственные подписи, обязательность и список подполей. Подполя тоже можно упорядочить. Нажмите «Сохранить настройки».
3. В каталоге нажмите «Создать запись» и выберите тип. Рабочий лист сразу показывает все выбранные строки в порядке профиля: **Код | Название строки | Значение**.
4. Вводите текст прямо в колонке значения. Enter переводит фокус к следующему видимому значению; Tab работает обычным образом. Дополнительные подполя раскрываются под строкой. Индикаторы перенесены в расширенные настройки строки и снабжены русскими описаниями.
5. Правый клик по строке или кнопка ⋯ открывает контекстное меню. Дублирование копирует значение и подполя, доступно только для повторяемых элементов. Обязательное поле нельзя удалить через меню; неповторяемое нельзя продублировать. Удалённую необязательную строку можно вернуть кнопкой под таблицей.
6. Нажмите «Сохранить запись» или Ctrl/Cmd+S. При выходе из изменённой записи появляется выбор: сохранить, продолжить ввод или закрыть без сохранения.

Настройки действуют отдельно для каждого типа. Изменения профиля отражаются и на открытой записи. Порядок отображения задаёт профиль; хранимый порядок уже существующих MARC-полей не меняется только от перестановки строк формы. При переключении типа ранее введённые данные сохраняются.

Пустые автоматически добавленные строки и подполя — элементы формы, в запись они не попадают. Ранее сохранённые пустые значения, пробелы, повторения и скрытые поля сохраняются. Если подполя в настройке не выбраны, форма показывает основные для распространённых полей; остальные можно добавить из списка. Для остальных тегов показываются неустаревшие подполя из справочника. Явный список подполей определяет их доступность и последовательность. Уже сохранённые подполя не удаляются при изменении настройки.

Полный JSON и маркер записи доступны в сворачиваемом блоке «Служебные данные записи». Исходная английская документация доступна в справочнике отдельным раскрывающимся блоком.

## Русский интерфейс

`frontend/src/ru.ts` содержит русские названия всех 291 тегов и отредактированные подписи основных подполей и индикаторов. `labels-ru.json` содержит 1685 переводов исходных подписей полей, подполей и значений индикаторов. Переводы вспомогательных и редких подписей получены автоматически; перед промышленным использованием специализированную терминологию следует проверить библиотекарю. Это интерфейсная локализация, а не официальный русский перевод стандарта. Названия можно переопределять в профиле документа.

Оригинальный справочник LOC не изменён: его контрольная сумма и тест воспроизводимого импорта сохраняют смысл. Подход к вводу — табличный рабочий лист с раскрываемыми подполями, как в привычных каталогизатору системах; коды остаются именно MARC21, а не внутренними кодами ИРБИС. Источник для изучения поведения рабочего листа: [руководство ИРБИС, редактирование записи](https://irbis128.ru/Documentation/php_irbis64/RedOS/RedOS.docx?id=Help%2FShow&m=Cataloguer%2FHelp%2FCataloguerGuide%2FEditRecord).

## MARC21: происхождение и воспроизводимость

Источник: [Library of Congress, MARC21 Bibliographic Field List](https://www.loc.gov/marc/bibliographic/ecbdlist.html), 1999 Edition, Update No. 42 (May 2026).

В `data/marc21.json` включены **291 уникальный числовой тег**, в том числе устаревшие элементы. Список не составлен вручную. `data/marc21.source.html` — исходный снимок страницы. JSON содержит URL, редакцию, SHA-256 оригинала, метаданные повторяемости, индикаторов, подполей, полное текстовое описание каждого блока, описание Leader/Directory. Источник содержит по два исторических определения 090 и 590: они объединены по тегу, альтернативы сохранены в `historical_variants` и документации. Устаревшие элементы помечены, но доступны.

Справочник загружается API из версионированного JSON при старте; отдельная таблица справочника не нужна. Интернет при обычном запуске не требуется, кроме скачивания образов и зависимостей при первой сборке.

Воспроизведение снимка (из корня проекта):

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
.venv/bin/python backend/app/import_marc.py --source data/marc21.source.html --output data/rebuilt.json
cmp data/marc21.json data/rebuilt.json
```

Получение новой версии с официального сайта:

```sh
.venv/bin/python backend/app/import_marc.py --output data/new-marc21.json
# Проверьте diff, редакцию, количество полей и тесты перед заменой текущего файла.
```

Импорт сохраняет исходный HTML рядом с JSON. При подозрительно малом количестве полей или неожиданных дубликатах активных тегов прекращается с ошибкой. После замены справочника перезапустите API. Тест точного количества тегов относится к текущему снимку: при обновлении стандарта его следует пересмотреть.

## Хранение и проверки

Таблицы `document_types` (настройки формы в JSONB) и `records` (полная запись в JSONB, версия, текст для поиска). Leader — строка, поля — упорядоченный массив, подполя — упорядоченный массив объектов `{code, value}`. Такой формат сохраняет повторения, порядок и пробелы; ключи JSON-объектов семантического порядка не имеют.

```json
{"leader":"00000nam a2200000   4500","fields":[
  {"tag":"245","ind1":"0","ind2":"0","subfields":[{"code":"a","value":"Название книги"}]},
  {"tag":"080","ind1":" ","ind2":" ","subfields":[{"code":"a","value":"004.8"}]}
]}
```

Проверяются форма JSON, теги, длина Leader, длина индикаторов и перечисленные значения, неповторяемые поля/подполя, обязательность полей профиля, длина 005/006/008, различие контрольных и обычных полей. Неизвестные числовые теги и неизвестные допустимые по форме коды подполей сохраняются с предупреждением; произвольные дополнительные ключи JSON отклоняются, а не молча отбрасываются. Неизвестные теги нельзя выдать за стандартные через настройку профиля.

Версия записи проверяется атомарным UPDATE: конфликт параллельного сохранения возвращает 409. Требуется повторно открыть запись и согласовать изменения. Профили пока не имеют подобной защиты.

Поиск регистронезависимый по всем значениям MARC, включая скрытые поля и классификацию. Есть фильтр по типу и страницы по 50 записей. `%` и `_` ищутся как буквальные символы, а не шаблоны SQL.

## Классификация

- УДК: 080$a.
- ББК: 084$a, источник 084$2 = `rubbk`; для поля 084 форма подставляет источник ББК, его можно изменить для другой системы.
- Предметные рубрики: 650$a и другие стандартные поля 6XX, подразделения — в соответствующих подполях. Выбор словаря отражается индикаторами и $2.

Источники: [084 Other Classification Number](https://www.loc.gov/marc/bibliographic/bd084.html), [Classification Scheme Source Codes](https://www.loc.gov/standards/sourcelist/classification.html). Полные таблицы УДК/ББК и авторитетные словари не поставляются; здесь ввод и поиск индексов и рубрик, а не редактор классификационной системы.

## Проверки

```sh
# Из корня проекта после установки Python-зависимостей:
cd backend
../.venv/bin/python -m pytest -q
# Или в контейнере (снимок справочника находится в /data):
docker compose -p standalone-library exec -e ADMIN_KEY=test-secret api python -m pytest -q
# Сборка интерфейса и проверка TypeScript:
cd ../frontend
npm ci
npm run build
npm test
```

Тесты проверяют воспроизводимость импорта, авторизацию, профили, ошибки структуры и повторяемости, классификацию, поиск, сохранность повторов и скрытых/локальных данных, конфликт версий. Эти API-тесты используют изолированную SQLite; отдельно проверен реальный запуск PostgreSQL и миграций через Compose. Результаты фактической проверки см. `VERIFICATION.md`.

Основные API: `GET /api/dictionary`, `GET/POST /api/types`, `PUT /api/types/{id}`, `GET/POST /api/records`, `GET/PUT /api/records/{id}`. Вход через `/api/auth/login`, затем cookie сеанса и `X-CSRF-Token` для изменений; см. AUTH.md. Список принимает `q`, `type_id`, `offset`, `limit` (до 100). `GET /api/health` проверяет доступность БД. При обновлении записи передавайте `version` из последнего чтения. Swagger доступен внутри контейнерной сети API на `/docs`.

## Ограничения MVP

- Не полная семантическая проверка MARC21: нет всех межполевых правил, проверок кодовых справочников, правил каталогизации RDA/AACR2, зависимостей фиксированных позиций от типа материала. Для 007 и Leader нет позиционного мастера; описания сохранены в справочнике. Справочник включает полный список тегов источника, но не полный текст всех отдельных руководств LOC.
- Нет ISO2709/MARCXML импорта/экспорта, MARC-8 преобразования, вычисления Directory и физических длин сериализованной MARC-записи. Сохранность относится к представленным данным JSON, не к побайтовому воспроизведению файла ISO2709.
- Есть пользователи, роли, индивидуальные права и журнал управления доступом. Нет MFA, восстановления пароля по почте и автоматического резервного копирования. Для внешнего доступа нужны HTTPS и эксплуатационная настройка.
- Поиск подстроки без морфологии и специализированного поискового индекса; для крупного каталога потребуется индексирование.
- Оригинальные описания LOC на английском, основной интерфейс и названия строк — на русском. Каталогизация не включает экземпляры, выдачу, читателей, комплектование или учёт фондов.
- Настройки формы поддерживают поля, обязательность, порядок и выбор подполей; отдельных правил обязательности подполей и сложных условных форм пока нет.

Браузерный сквозной тест (создаёт демонстрационную запись в запущенном каталоге):

```sh
cd frontend
npm ci
npx playwright install chromium
node tests/browser.cjs
# Для установленного Chrome можно задать CHROME_PATH=/полный/путь/к/Chrome
```

Тест читает ключ из `../.env`, создаёт отдельный тестовый тип, проверяет рабочий лист, правый клик, ограничения повторения/удаления, перестановку полей, сохранение без пустых строк, скрытые данные и поиск на русском. Сохраняет `preview.png`, `preview-settings.png`, `preview-mobile.png` и идентификаторы созданных данных в `test-created.json`. Запускайте на тестовом экземпляре; тест сам не удаляет созданный тип и запись.

## Обновление от 20 октября 2026: MARCSQL и ГОСТ

Рабочие листы настроены по скриншоту пользователя с буквальными локальными кодами MARCSQL; добавлены согласованные строки для описания по ГОСТ Р 7.0.100–2018. Подполя видны сразу, все типы получают один исходный профиль. Выходное описание формируется отдельно от таблицы ввода, с замечаниями и ссылками на пункты стандарта.

Подробное соответствие, различия локальных кодов и MARC21, принятые решения и **границы поддержки стандарта**: [GOST.md](GOST.md). Полное соответствие всему ГОСТ не заявляется: сейчас это помощник подготовки проверяемого каталогизатором черновика.


## Автоматические служебные поля

001, 005, начальное 008, маркер и локальные даты создания заполняются при сохранении. В форме служебные строки защищены; для общих характеристик 008 есть отдельная панель. Правила сохранения исходных данных и ограничения описаны в [TECHNICAL.md](TECHNICAL.md).


## Справочники значений

Во вкладке «Настройка ввода» раскройте у поля «Справочники значений», выберите подполе, включите справочник и при необходимости автопополнение. Сохраните настройки, затем добавьте значения и пояснения. В форме кнопка ▾ открывает список с поиском. Новые ручные значения попадают в справочник после успешного сохранения записи. [Подробная инструкция](VOCABULARIES.md).


## Навигация и удаление записей

После входа и при нажатии «Каталогизация и классификация» открывается каталог записей. Стрелка рядом раскрывает скрытое по умолчанию подменю «Настройка ввода» и «Справочник полей». При выходе из изменённой записи сохраняется предупреждение о несохранённых данных.

Удаление отдельной записи доступно из списка и из сохранённой карточки. Окно подтверждения показывает заглавие и номер; удаление необратимо. Тип документа и значения справочников остаются. Сервер требует право удаления и актуальную версию записи: DELETE /api/records/{id}?version={version}; конфликт версий возвращает 409. Массового удаления нет.

## Импорт из MARCSQL

Добавлен ручной импорт `dbo.DOC` из Microsoft SQL Server через отдельный API. По умолчанию — предварительный просмотр трёх записей. Порядок запуска и ограничения: [MARCSQL_IMPORT.md](MARCSQL_IMPORT.md). Импорт не запускается при старте приложения.

## Рабочий лист по уточнённым скриншотам (20 октября 2026)

Для всех типов используется новый порядок MARCSQL: добавлены 090$c, 700$a, 245$n/$p, 246$a, 256$a, 440$a, 520$a, 541$n, 650$a, 856$d/$f, 900$a, 901$t, расширенные 952 и 990, 998$a. Ранее согласованные дополнительные строки для ГОСТ сохранены. 990$d/$e/$f автоматические, остальные подполя 990 доступны для ручного ввода и справочников. Обложка и макрообъект пока являются текстовыми значениями, загрузка изображений не реализована.

Команда `python -m app.apply_worksheet --backup /tmp/profiles.json` явно обновляет формы всех типов с сохранением привязок справочников для оставшихся полей; перед обновлением записывает резервную копию настроек. Сами записи каталога команда не изменяет.

Цена приобретения вводится в 541$h рядом с количеством/объёмом, свободным текстом с валютой (например, `5 000 ₸`). Подполе необязательное; оно не включается в библиографическое описание. Основание: https://www.loc.gov/marc/bibliographic/bd541.html .

## Поступления и экземпляры

В боковом меню «Поступления» кнопка «Новое поступление» регистрирует партию с датой, источником, накладной и одной или несколькими книгами. Экземпляры партии создаются один раз, суммы учитываются по валютам.

В редактировании записи → «Экземпляры» → «Создать экземпляр» добавляется один экземпляр **имеющегося фонда**, без накладной и без поступления. Он не включается в статистику новых поступлений для КСУ. Сохранение описания само по себе экземпляры не создаёт.

Есть история индивидуальных сведений, защита от дубликатов запросов и удаления записи с экземплярами. Полная форма КСУ пока не реализована; списание и исправление поступлений описаны ниже. Правила, API и ограничения: [ACQUISITIONS.md](ACQUISITIONS.md).

## Списание и исправление ошибок

Отдельная вкладка «Списание» позволяет найти конкретный экземпляр по инвентарному номеру и списать его с датой, причиной и номером акта. В поступлениях доступны исправление заголовка, стоимости и состава партии, добавление забытых книг и отмена ошибочного поступления. История сохраняется; отменённые и списанные экземпляры исключаются из действующего фонда. [Правила, API и ограничения](STOCK_OPERATIONS.md).

## Импорт экземпляров MARCSQL

Подготовлен перенос обычных строк INV как имеющегося фонда, с привязкой к ранее импортированному DOC_ID, сохранением исходных номеров/штрихкодов и полным архивом строк. Спорные четыре строки пропускаются, даты не угадываются. Источник только читается; запуск выполняет пользователь. [Одна команда для каталога и экземпляров, отчёты и ограничения](MARCSQL_COPIES_IMPORT.md).

Поиск по ISBN доступен в новой записи: «Найти по ISBN». Источники —
[Open Library Books API](https://openlibrary.org/dev/docs/api/books) и
[Google Books](https://developers.google.com/books/docs/v1/using).
ISBN проверяется по контрольной цифре, ISBN-10 приводится к ISBN-13.
Данные показываются отдельно по источникам; пользователь выбирает строки для вставки.
Заполненные строки по умолчанию не выбраны. Поиск ничего не сохраняет в каталог.
Название, авторы, издательство, дата, место и объём переносятся только при наличии
в ответе. Авторы требуют проверки формы имени; сведения об ответственности, УДК,
ББК, язык, цена и экземпляры автоматически не выводятся из этих результатов.
Внешние сервисы могут не найти издание или ограничить запросы; ошибки показываются
отдельно. Google Books может требовать API-ключ: передайте `GOOGLE_BOOKS_API_KEY`
в окружение сервиса api. Без ключа используется доступный публичный запрос,
при отказе остаётся Open Library. Legacy Books API Open Library может быть изменён
провайдером; адаптер изолирован в `app/isbn_lookup.py`.

### КСУ — поступления

В боковом меню добавлен первый лист книги суммарного учёта по образцу АМИР.xlsx: автоматические строки из поступлений и каталога, соответствия кодов литературы, годовые итоги и Excel. Отдельное заполнение КСУ не требуется. Порядок работы и ограничения: [KSU.md](KSU.md). Для сотрудников назначаются отдельные права КСУ; администратору доступны все функции.

### Статистика сотрудников

«Статистика → Работа сотрудников» показывает созданные и изменённые записи, общий итог,
итоги сотрудников и список книг с переходом в карточку. Доступ: `statistics.view` (у администратора автоматически).
Период включителен по датам Алматы; без дат — всё время. Каждая запись считается один раз
в каждой категории у каждого сотрудника. Общий итог уникальных книг не равен сумме категорий
или сотрудников, если одну книгу обрабатывали несколько раз. Число содержательных сохранений
видно в списке отдельно. Сохранения без изменений, автоматическая дата 005 и смена статуса
маркера n→c не увеличивают показатели. Автор действия — вошедший пользователь, не поле 097$b.
Учёт начинается с миграции 0012; старые действия и импорт не восстанавливаются задним числом.
История сохраняет заглавие и имя на момент действия, остаётся после удаления записи или пользователя.
Это журнал работы с библиографическими записями; операции с экземплярами, поступлениями и КСУ не входят.

В настройках справочника каждой строки доступно «Разрешить редактирование выбранного значения».
Этот флаг разрешает свободный ввод и изменение выбранного значения в новых и существующих карточках.
Без автопополнения изменённое значение сохраняется только в карточке, исходный справочник не меняется.
При включённом автопополнении новое значение также добавляется в справочник.
По умолчанию флаг выключен; существующие настройки продолжают работать как прежде.

Справочник 097$b «Оператор» формируется из ФИО активных, неудалённых пользователей.
Управляйте этим списком в разделе пользователей. При содержательном изменении существующей
карточки 097$b заменяется ФИО вошедшего сотрудника на сервере; простое сохранение без изменений
оставляет прежнего оператора. Новые карточки сохраняют возможность поправить подставленное ФИО.
Импорт не изменён. Статистика по-прежнему использует идентификатор вошедшего пользователя.
Миграция 0013 добавляет во все типы 35 значений 952$a с пояснениями из предоставленных библиотекой
фотографий. Существующие дополнительные значения и непустые пояснения не удаляются.
Новые типы с полем 952 также получают этот справочник автоматически.

### Печать бланков экземпляров

В сохранённой карточке книги откройте «Экземпляры» → «Печать бланков экземпляров». Загружаются все действующие экземпляры этой записи, независимо от страницы и поиска в списке. Списанные и отменённые экземпляры исключены. Печать не меняет каталог или учёт.

По умолчанию: 40 × 100 мм, три столбца, шесть бланков на A4; размер и число столбцов можно изменить перед печатью. В диалоге браузера: A4, масштаб 100%, колонтитулы отключены. Доступно сохранение в PDF. Если текст не помещается, печать блокируется до увеличения размера.

Данные: полочный индекс 090$a (при отсутствии — 080$a), автор 100$a, заглавие 245$a и 245$b, год 260$c (при отсутствии — 264$c с индикатором 2 = 1). Инвентарный номер и цена берутся из экземпляра, отсутствующая цена обозначается «—», нулевая — «0.00». Для KZT валюта на бланке не подписывается; другие валюты подписаны. Используется сохранённая версия карточки — сначала сохраните изменения.
