# Библиографическая запись и копирование

Актуально: 3 ноября 2026 года.

## Основание

Владелец предоставил `701002018.pdf`: ГОСТ Р 7.0.100–2018
«Библиографическая запись. Библиографическое описание. Общие требования и
правила составления», 132 страницы PDF, включая поправку ИУС № 3–2020.
SHA-256: `ff0a3d1aadc8bac946ceeee83864a2e9c44b4aeba69a824a551838574baf14bd`.
PDF не включён в репозиторий. Правила проверены по самому документу, а не по имени файла.

Это автоматическая сборка заполненных сведений, а не полная проверка соответствия
всем положениям стандарта. Неизвестные сведения не подставляются. Специальные
материалы, многоуровневые описания и выбор источников требуют работы каталогизатора.

## Что получает сотрудник

В карточке каталога рядом с «Заполнить по фото» расположена кнопка
«Копировать библ. запись». Работает с существующей и новой карточкой: берёт снимок
текущих полей при нажатии, в том числе несохранённые изменения. Само копирование
ничего не сохраняет в БД. При открытом необработанном JSON кнопка отключена.

Кнопка «Копировать» в строке общего каталога использует сохранённую запись.
Нижний блок карточки «Библиографическая запись · ГОСТ Р 7.0.100–2018» позволяет
сформировать тот же текст, увидеть замечания к отсутствующим сведениям и выбрать
описание составной части (статьи). Предупреждение об устаревшем предпросмотре
сохраняется: повторное копирование всегда берёт актуальные поля.

Сохраняются язык и написание исходных значений. Заголовок из поля 100 не
переводится, не сокращается до инициалов и не подставляется вместо 245$c.
Если браузер запрещает доступ к буферу обмена, открывается окно с выделенным
текстом для ручного Ctrl+C / ⌘C.

## Сборка и источники правил

- Порядок областей: п. 4.3; разделение областей знаком «. — » и конечная точка:
  пп. 4.6.1–4.6.3; пробелы и совмещение пунктуации: пп. 4.6.5, 4.6.10–4.6.11.
- Заглавие 245$a, связанные сведения 245$b, номер/название части 245$n/p и
  ответственность 245$c: пп. 5.2, 6.2.6.1. Ответственность отделяется « / »,
  связанные сведения « : ». Повторные сведения об ответственности — « ; ».
- Издание 250$a/b: п. 5.3. Публикация 260$a/b/c либо 264 с ind2=1 при отсутствии
  заполненных выходных сведений 260: п. 5.5. Место, издатель, дата соединяются
  « : » и «, »; порядок нескольких мест/издателей сохраняется.
- Физическая характеристика 300$a/b/c/e: п. 5.6. Единицы объёма должны быть
  указаны в каталоге, их нельзя угадывать по одному числу.
- Серия 490, при отсутствии заполненной 490$a — 440: п. 5.7. Названия частей
  n/p, ISSN из $x после запятой (п. 5.7.7), выпуск $v после « ; » (п. 5.7.8).
  Каждая серия в отдельных круглых скобках, между сериями пробел (п. 5.7.10).
- Примечания 500$a, URL и доступ 856$u/z; ISBN 020$a и ISSN 022$a, уточнения
  $q в скобках: пп. 5.8–5.9. Повтор уже введённого префикса ISBN/ISSN убирается.
- Вид содержания и средство доступа: заполненное 245$z либо текстовые
  336$a / 337$a, п. 5.10. Сырые коды автоматически не расшифровываются.
- Для составной части сведения 773$t/d/g присоединяются через « // » после
  описания составной части, согласно разделу 7. Поддержка специальных случаев
  аналитического описания остаётся ограниченной.

По п. 4.1 заголовок записи и библиографическое описание — разные элементы;
правила составления заголовка относятся к ГОСТ 7.80. Как в примерах приложения А,
копируемая **запись** может предваряться уже имеющимся личным заголовком из первого
заполненного 100$a (с имеющимися $b/c/d/q). Если заголовка нет, выводится описание
без него. Программа не решает автоматически, какой заголовок должен быть у книги.

Граничные знаки, уже введённые сотрудником в конце/начале соседних подполей,
не дублируются при добавлении такого же разделителя. Внутренняя пунктуация,
сокращения, вопросительные знаки и многоточия сохраняются.

## Код и совместимость

`backend/app/gost.py` — единый форматтер. В обоих API результат содержит:

- `text` — библиографическое описание, прежняя семантика сохранена;
- `heading` — имеющийся личный заголовок либо пустая строка;
- `record_text` — заголовок и описание для копирования/предпросмотра;
- `issues`, `requires_review`, `scope` — замечания и границы автоматизации.

`GET /api/records/{id}/description` берёт сохранённый MARC.
`POST /api/gost/preview` принимает текущий MARC и вид описания.
Оба требуют `catalog.view`; POST использует обычную защиту сеанса/CSRF.
API не меняют записи. Старые потребители `text`, включая статистику, совместимы.

`frontend/src/copyDescription.ts` выбирает источник и снимает копию текущих
данных. `CopyDescription.vue` отвечает за буфер обмена и ручной вариант;
`App.vue` использует компонент и в списке, и в карточке.

Тесты: `backend/tests/test_gost.py` (в том числе книжный пример Каменского из
приложения А, PDF стр. 111 / печатная стр. 107), проверка API и прав в
`test_circulation_statistics.py`, `frontend/tests/copyDescription.test.ts`.
Проверены также копирование из браузера, несохранённые правки, новая запись,
ручной вариант при запрете буфера и отсутствие записи в БД при копировании.
Миграция не нужна; обновляются образы `api` и `web`.
