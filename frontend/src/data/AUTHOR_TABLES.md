# Авторские таблицы для поля 090$x

Справочник использует два PDF, предоставленных владельцем проекта 3 ноября 2026 года:

- `cyrillic.pdf` — «Авторские таблицы», Л. Б. Хавкина, двузначные; 21 страница. Таблица на страницах 2–15, правила на 16–21.
- `latin.pdf` — латинская таблица; 16 страниц. Таблица на страницах 2–14, правила на 15–16.

Это копии конкретных присланных файлов, а не заявление о полноте всех современных авторских таблиц. Оригиналы открываются из окна подбора на нужной странице PDF (с поддержкой навигации в PDF-просмотрщике браузера).

SHA-256 оригиналов:

```
cyrillic.pdf b3a36b51e2fd262788f98d37dcc4deb9d011b110879452b14fbab1c97af5231d
latin.pdf   c11446a4d95d6061d58ecdbc86a362f6d2e4267ba3a9f6f22678849a3a0680ed
```

## Данные и подбор

`src/data/authorTables.json` содержит 4 742 строки: 28 кириллических букв × 89 номеров (11–99) и 25 латинских групп × 90 номеров (10–99), I/J объединены. Кириллический скан распознан OCR и сверен по всем 14 страницам таблицы; латинский текст извлечён из PDF и сверен с его изображениями. Номер строки вычисляется как `start + index`, `page` — номер страницы в PDF, начиная с 1.

Подбор в `src/authorMarks.ts` использует нижнюю алфавитную границу, а не самое длинное совпадение префикса. Например, Мосолов → М82, хотя в таблице есть строка «Мос» → М81. Для латиницы диакритика не влияет на порядок, I/J объединены в любой позиции. Для кириллицы Ё/Й при сравнении внутри слова приводятся к Е/И; начальные Ё/Й/Ъ/Ы по правилу 3 дают только букву. Казахские буквы, которых нет в этих файлах, не транслитерируются автоматически.

Начальная буква сохраняется в знаке, в том числе J. Разделитель по умолчанию отсутствует; для кириллических З/О/Ч и латинских I/O по правилам файлов ставится дефис. Оператор может выбрать пробел, дефис или отсутствие разделителя. Число цифр фиксировано: оба источника двузначные.

Берётся первое слово фамилии или заглавия. Порядок ФИО программа не угадывает. Заглавие, начинающееся цифрами, нужно ввести словами. Произвольное автоматическое преобразование знака по языку книги не выполняется.

## Неоднозначности исходного PDF

В латинском файле есть ошибки самого источника: например, A31 «Aid», A39 «Aim», A40 «Ale», B35/B37 «Bee», L19 «Lai», I54 «11». Такие строки сохранены с `review: true`. Для них и затронутых интервалов нет автоматической рекомендации. Оператор может свериться с оригиналом, вручную выбрать строку и подтвердить проверку. Предполагаемые исправления слогов не выдаются за исходные данные.

Исключение Lai/Laj → L17 подтверждено явным примером на странице 16 латинского PDF; он имеет приоритет над ошибочным повтором «Lai» в L19. Это отдельно документировано и проверяется тестом.

`special: true` отмечает специальные кириллические знаки КПСС, Ленина В. И., Маркса К., СССР, Толстого Л. Н., Энгельса Ф. Их нельзя автоматически назначать любому человеку с той же фамилией. Требуется проверка соответствия автору/организации; окно запрашивает её даже при точном совпадении или поиске по номеру знака.

## Применение

`AuthorMarkInput.vue` оборачивает существующий `VocabularyInput`. Кнопка доступна у 090$x и в основной, и в дополнительной строке рабочего листа. Автор 100$a или заглавие 245$a используются только как начальный запрос. До нажатия «Вставить» карточка не меняется; затем обычное сохранение записи сохраняет знак. Повторения 090 независимы.

Ручной ввод и настроенный пользователем справочник остаются. Если поле имеет закрытый список (`auto_add=false`, `allow_edit=false`), вставка нового значения из авторских таблиц запрещена, пока оно не разрешено в настройках. Серверная валидация не обходится. Для работы не нужны OpenAI, миграции, импорт данных в БД или внешние запросы: JSON подгружается локально при первом открытии окна.

Проверки: `npm test` и `npm run build` из `frontend`. Тесты проверяют полноту, порядок надёжных строк, примеры из источников, специальные знаки, неоднозначности, форматирование, ограничения справочника и SHA-256 оригиналов. Изменение значений JSON требует сверки с PDF, а не догадки по соседним строкам.
