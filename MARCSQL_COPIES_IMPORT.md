# Повторный импорт каталога и экземпляров

MARCSQL используется **только для чтения**. Подключение к нему и импорт запускает пользователь; агент к источнику не подключается. Все изменения выполняются в локальном PostgreSQL приложения.

## Запуск после согласованной очистки

Из папки проекта:

```sh
docker compose -f compose.yaml -f compose.import.yaml run --rm importer python -m app.import_marcsql_all --apply
```

Команда сначала переносит весь `dbo.DOC`, затем `dbo.INV` через локальный API. Если первый этап завершается с ошибками, второй не начинается. При обрыве повторите ту же команду с начала: каталог защищён парой `(MARCSQL_SOURCE, DOC_ID)`, экземпляры — `(MARCSQL_SOURCE, INV_ID)`. Изменённые оригиналы и конфликты номеров не перезаписывают локальные данные, а попадают в ошибки.

Ожидаемый объём по предоставленной пользователем выборке: 9867 библиографических записей; 51474 строки INV, из них 51470 обычных экземпляров и 4 намеренных пропуска. Фактические числа зависят от текущего содержимого источника; несовпадения и ошибки нужно проверить по отчёту, а не считать автоматически успешным переносом всех данных.

Отчёты сохраняются во внутреннем томе Docker, вне общей папки macOS:

- `/import/reimport-catalog.jsonl` — каталог;
- `/import/reimport-copies.jsonl` — экземпляры и пропуски.

Отчёты дописываются при повторных запусках. Показать только ошибки и пропуски экземпляров, без подключения к источнику:

```sh
docker compose -f compose.yaml -f compose.import.yaml run --rm importer python -c 'import json; from pathlib import Path; rows=(json.loads(line) for line in Path("/import/reimport-copies.jsonl").read_text().splitlines() if line.strip()); [print(json.dumps(row, ensure_ascii=False)) for row in rows if row.get("status") in ("error", "skipped")]'
```

## Отдельные этапы и предварительный просмотр

После импорта каталога посмотреть первые три экземпляра без записи:

```sh
docker compose -f compose.yaml -f compose.import.yaml run --rm importer python -m app.import_marcsql_copies
```

Запустить только все экземпляры:

```sh
docker compose -f compose.yaml -f compose.import.yaml run --rm importer python -m app.import_marcsql_copies --apply --limit 0
```

Проверить настройки без сети:

```sh
docker compose -f compose.yaml -f compose.import.yaml run --rm importer python -m app.import_marcsql_copies --check-config
```

## Правила переноса INV

Согласованная группа: `INVMODE='I'`, `STATE=1`, `CNT=1`, `OFFDATE` пусто или 0. Значения справочника STATES для выдачи книг не используются как расшифровка INV.STATE. Три строки с датами предполагаемого списания и одна строка режима U пропускаются; полный оригинал пропущенной строки включается в отчёт.

| Поле приложения | Источник |
|---|---|
| Книга | По архиву каталога: тот же MARCSQL_SOURCE и DOC_ID |
| Инвентарный номер | T090e, текст, начальные нули сохраняются |
| Штрихкод | T876p, текст, начальные нули сохраняются |
| Сигла | T090f, при пустом значении — SIGLAS.SHORTNAME по SIGLA_ID |
| Цена | T876c, точное десятичное число; пусто и 0 различаются |
| Валюта | KZT — принята для этого переноса, в INV отдельного поля валюты не предоставлено |
| Источник | SOURCE |
| Примечание | NOTES |
| Дата поступления / проверки | Пусто: REGDATE и DATE1 не интерпретируются без подтверждения |

Пустой штрихкод получает служебный уникальный идентификатор `MARC-NOBARCODE-<источник>-<INV_ID>`. Это явно не исходный штрихкод; в отчёте есть `barcode_generated: true`, оригинальное пустое значение сохранено. Инвентарные номера не выдумываются: если T090e пуст, строка отклоняется.

Экземпляры импортируются как **имеющийся фонд**, без поступлений, списаний или изменения статистики новых поступлений. Все поля INV, включая CUSTOM*, INVP, исходные числовые даты и статусы, сохраняются в JSON-архиве. Прочитать оригинал: `GET /api/copies/{id}/marcsql-source` с ключом администратора.

Источник читается фиксированным SELECT по 100 строк с LEFT JOIN справочника SIGLAS. Пакеты по 100 отправляются в локальный API; ошибки отдельных строк не откатывают успешно обработанные соседние строки. При сетевой ошибке повтор безопасен, в том числе если ответ потерялся после сохранения. Изменения в источнике во время чтения не образуют единого снимка — на время переноса желательно приостановить редактирование MARCSQL.

## Очистка локального приложения

Очистка — отдельная явно разрешаемая операция, не часть импортёра. Перед ней остановлены локальные api/web, создана полная резервная копия PostgreSQL. Удаляются только описания, экземпляры, поступления, списания, история и привязки предыдущих импортов. Типы документов, их настройки, справочники значений и официальный справочник MARC сохраняются. ID не переиспользуются.

`python -m app.reset_local_catalog` без флагов только показывает количества. Применение требует одновременно `--apply --confirm RESET_LOCAL_CATALOG`; скрипт проверяет локальную цель PostgreSQL `db/catalog` и вообще не импортирует драйвер SQL Server. Операция транзакционная. Не запускайте её повторно после успешного импорта.
