# Перенос каталога MARCSQL по сети

Импорт запускается только вручную. Подключение к источнику и реальный перенос разработчиком не выполнялись.
Используется SQL Server `10.0.1.16:1433`, база `marc`, таблица `dbo.DOC`.
Драйвер: [pymssql](https://www.pymssql.org/en/stable/ref/pymssql.html).
Пароль находится только в локальном `.env.marcsql` (права 600), не в исходниках.
На другом компьютере скопируйте `.env.marcsql.example` в `.env.marcsql` и заполните пароль.

## Подготовка

Откройте терминал в папке проекта. Приложение должно работать, сервер SQL Server должен быть доступен из Docker по локальной сети.

```sh
docker compose up -d --build api
docker compose -f compose.yaml -f compose.import.yaml build importer
```

Проверьте `IMPORT_TYPE_MAP` в `compose.import.yaml`: ключ — `RECTYPE/BIBLEVEL`, значение — ID типа в приложении (`GET /api/types` после входа через `/api/auth/login`; см. AUTH.md).
Карта в текущей установке: `a/m` → 1 (Книга), `a/a` → 2 (Научная статья), `a/c` → 6 (Коллекция), `a/s` → 7 (Сериальное издание).
При переносе проекта в новую базу создайте недостающие типы в настройках ввода и укажите их фактические ID в `IMPORT_TYPE_MAP`: ID 6 и 7 не создаются сидированием автоматически.
Типы Коллекция и Сериальное издание в текущей установке используют копию настроек полей типа Книга. Исходный библиографический уровень сохраняется при импорте.
Значения c (Collection) и s (Serial) проверены по [официальному описанию Leader/07](https://www.loc.gov/marc/bibliographic/bdleader.html).
Это соответствие нужно проверить в вашей установке. Неизвестные комбинации пропускаются с ошибкой, не назначаются автоматически.
Не все аналитические записи являются научными статьями: при необходимости создайте отдельный тип.

## Предварительный просмотр трёх записей

```sh
docker compose -f compose.yaml -f compose.import.yaml run --rm importer
```

Ничего не сохраняется в каталог приложения. Разобранные записи и предупреждения сохраняются в `/import/report.jsonl` во внутреннем томе Docker `import_reports`, без общей папки macOS. Старый `import/type-map.json` больше автоматически не читается.

Показать отчёт без подключения к базе:

```sh
docker compose -f compose.yaml -f compose.import.yaml run --rm importer python -m app.import_marcsql --show-report
```

Проверить настройки и запись в том без сети:

```sh
docker compose -f compose.yaml -f compose.import.yaml run --rm importer python -m app.import_marcsql --check-config
```

Проверьте русские/казахские буквы, повторяющиеся подполя, индикаторы и тип документа.

## Пробный перенос и весь каталог

Следующая команда уже сохраняет три записи:

```sh
docker compose -f compose.yaml -f compose.import.yaml run --rm importer python -m app.import_marcsql --apply --limit 3
```

После проверки в приложении:

```sh
docker compose -f compose.yaml -f compose.import.yaml run --rm importer python -m app.import_marcsql --apply --limit 0
```

Источник читается порциями по 100 записей; каждая запись сохраняется отдельной транзакцией через API.
При обрыве повторите команду: одинаковые `(MARCSQL_SOURCE, DOC_ID)` пропускаются.
Изменившийся оригинал возвращает конфликт, правки в приложении не перезаписываются.
Можно использовать `--after ID`, но это пропустит более ранние ошибки; безопаснее повторить с начала.
Отчёт дописывается при каждом запуске. Ошибки отдельных записей не останавливают остальные; итоговый код завершения 1 означает наличие ошибок.
Импорт не является синхронизацией: обновления/удаления источника автоматически не переносятся.
Во время переноса желательно не редактировать исходный каталог: чтение не фиксирует единый снимок всей базы.

## Сохранность и ограничения

- Все разобранные поля, подполя, повторы и индикаторы сохраняются независимо от видимости в форме.
- Исходный `ITEM`, `DOC_ID`, `RECTYPE`, `BIBLEVEL` и контрольная сумма сохраняются отдельно.
  Оригинал доступен через `GET /api/records/{id}/marcsql-source` с ключом администратора.
- Дополнительный путь в `001` хранится в оригинале; в форме отображается номер из подполя `0`.
- Маркер строится для модели приложения из типа/уровня и статуса; исходный нестандартный `000` остаётся в оригинале.
- `005`, `008`, `990` при импорте не обновляются. Пропущенные служебные поля не генерируются.
- Исторические нарушения правил описания выводятся предупреждениями. Последующее редактирование проходит обычную валидацию и может требовать исправления этих нарушений.
- Неизвестная структура разделителей/кодов отклоняется. Разбор проверен на предоставленном формате; другие диалекты требуют отдельного примера.
- Справочники значений автоматически не пополняются импортом.
- Экземпляры импортируются отдельным этапом, см. MARCSQL_COPIES_IMPORT.md. Выдачи, читатели и файлы `MOBJECT` не импортируются.
- После удаления записи в приложении оригинал остаётся в архиве; повторный импорт не восстанавливает её автоматически.
- В SQL Server выполняются только SELECT. Права учётной записи `marc` не проверены; для постоянной работы предпочтителен пользователь только с чтением.
