# Книговыдача

Модуль использует существующие библиографические записи, экземпляры, карточки читателей, пункты обслуживания и учётные записи. AD и Platonus остаются источниками реестра людей: поиск читателя и выдача выполняются в локальной БД. Посещения не создаются при выдаче.

## Сотруднику

1. Откройте «Книговыдача → Выдача», отсканируйте билет или найдите читателя по ФИО и выберите нужного человека.
2. Отсканируйте штрихкод или введите инвентарный номер книги, нажмите «В корзину». Повторите для остальных книг. ISBN показывает издание, после него обязательно выбрать конкретный экземпляр.
3. Проверьте сроки. При изменении срока укажите причину. Нажмите «Подтвердить выдачу». Корзина сохраняется целиком либо не сохраняется вовсе.
4. Для возврата откройте «Возврат», отсканируйте книгу, проверьте читателя и состояние, подтвердите. Для повреждения или утраты опишите обстоятельства. Утрата не считается физическим возвратом.
5. Продление доступно у открытой выдачи. В «Истории» можно найти операции по читателю, коду экземпляра, периоду и пункту обслуживания; кнопка «История операции» показывает события и прежние сроки.
6. В «Бронях» сотрудник подтверждает физическую готовность выделенной книги. До этого её нельзя выдать даже владельцу брони. Приостановленную очередь можно проверить повторно после устранения причины.
7. В «Штрафах» оплата означает отметку сотрудника, а не банковскую транзакцию. Оплата не закрывает инцидент. Решение по делу оформляется отдельно во вкладке «Инциденты».

## Правила и права

Начальные настройки: лимит 10 открытых выдач; предупреждение за две книги до лимита. На издание с 1–2 экземплярами даётся 3 дня, с 3–5 — 5 дней, с 6 и более — 7 дней. Утраченные и списанные экземпляры исключаются из количества. Это политика приложения, а не требование ГОСТ.

Даты рассчитываются по Asia/Almaty до конца дня, хранятся в UTC. Обычная ручная дата — до 30 дней, расширенная требует специального права и причины; абсолютный предел — 365 дней. При очереди других читателей нельзя увеличить рассчитанный срок. Продление по умолчанию одно, на 14 дней от прежнего срока. Просроченные и закрытые выдачи не продлеваются.

Штраф за календарный день просрочки по умолчанию 0 (отключён), начисляется при возврате. Предполагаемая утрата по умолчанию отключена; включение создаёт дело, но не закрывает выдачу и не списывает книгу. Бронь: до 3 активных на читателя, подготовка и получение по одному дню, одно продление получения. Очередь FIFO по времени и ID; неподходящий читатель переводится в «Требует проверки» с причиной, освобождая книгу следующему.

Все параметры доступны в «Книговыдача → Настройки». Индивидуальный лимит задаётся после выбора читателя.

Роль «Библиотекарь» предлагает выдачу, возврат, продление, свои операции и бронирования без права обхода ограничений. «Руководитель» предлагает расширенные права; администратор имеет полный доступ. Права проверяются на сервере. Существующим пользователям новые разрешения нужно назначить в «Пользователи и права»: их старые права автоматически не расширяются.

Роль «Читатель» имеет только свои книги и собственное продление. Администратор создаёт такую учётную запись и связывает её с карточкой в «Читателях». Это локальная авторизация, не автоматический вход через AD/Platonus. Чужой ID выдачи не предоставляет доступ.

Отдельные разрешения: circulation.issue / return / renew, override_limits, override_due_date, view_any_history, view_own_history, settings, copies; loans.view_own / renew_own; reservations.manage; incidents.manage; fines.manage / waive. Просмотр фото требует readers.registry.view, поиск по ИИН — readers.personal_data.view.

## Данные и целостность

Миграция `0016_circulation` после `0015_readers_visits` добавляет таблицы выдач, событий, физического состояния экземпляра, броней, штрафов, инцидентов, аудита, настроек, ключей повторных операций и локальных уведомлений. Существующие каталоги и читатели не пересоздаются.

`Copy.status` остаётся источником состояния фонда. Физическое состояние и ограничение доступа хранятся отдельно. Доступность вычисляется из фонда, физического состояния, открытой выдачи и закреплённой брони. Статусы не дублируются независимо. `closed_at` закрывает выдачу; `returned_at` означает только физический возврат, `lost_at` — фиксацию утраты.

Частичные уникальные индексы PostgreSQL запрещают две открытые выдачи одного экземпляра, повторную активную бронь читателя на издание и два активных закрепления экземпляра. Внешние ключи сохраняют историю. Триггер запрещает списание/отмену экземпляра с открытой выдачей или закреплённой бронью. Ограничение непустого штрихкода добавлено NOT VALID: старые строки сохраняются, новые/изменяемые должны проходить проверку.

Изменения, события, аудит и уведомления сохраняются одной транзакцией. Повтор операции защищён ключом в области сотрудника и вида операции, данные того же ключа нельзя изменить. Версии защищают от устаревших форм. Используются блокировки строк читателя и экземпляров; для текущего масштаба есть общая транзакционная блокировка записей приложения и фоновой обработки. Это сознательный компромисс: операции записи сериализуются, для большого потока понадобится уменьшить область блокировок с сохранением проверок гонок.

## Развёртывание

Сначала создайте резервную копию штатным `./deploy/backup.sh`. Обновите исходники и пересоберите API и web. При старте API автоматически выполняет `alembic upgrade head`. Не удаляйте Docker volumes и не запускайте очистку или повторный импорт ради этой миграции.

Дополнительно подключите `compose.circulation.yaml` **к тому же проекту Compose и тем же файлам окружения/настройкам читателей**, с которыми запускаете приложение. Пример для сервера без дополнительных overlays:

```sh
docker compose -p kaztbu-catalog-v2 --env-file .env.server \
  -f compose.server.yaml -f compose.circulation.yaml \
  up -d --build api web circulation-worker
```

Если настроена ночная синхронизация читателей, сохраните её env-файлы, overlays и профили в этой команде; не заменяйте конфигурацию рабочего API сокращённым примером. Для локальной конфигурации базовый файл `compose.yaml`, имя проекта `standalone-library`.

`circulation-worker` — отдельный постоянно работающий процесс с restart unless-stopped, запускает проверку каждые 60 секунд. Он переводит просроченные выдачи, создаёт напоминания на завтра, обрабатывает истечение броней и необязательную предполагаемую утрату. Проверки просрочек при выдаче и продлении работают и без worker.

Разовый запуск (с теми же параметрами Compose):

```sh
docker compose -p kaztbu-catalog-v2 --env-file .env.server \
  -f compose.server.yaml -f compose.circulation.yaml \
  run --rm circulation-worker python -m app.circulation_worker --once
```

Уведомления находятся в БД и видны в интерфейсе после успешного сохранения. Ключ напоминания включает срок выдачи. Email/SMS и внешняя очередь доставки не подключены и не заявляются работающими.

## Ограничения

- Выдача на дом для экземпляров читального зала запрещена; отдельный процесс читального зала не реализован.
- Межфилиальная доставка не реализована. Бронь с конкретным пунктом ждёт экземпляр именно там; статус перемещения не означает выполненную доставку.
- Реальное списание выполняется существующим разделом «Списание», не автоматически из инцидента. Замещающий экземпляр регистрируется штатно; решение «Замена» требует уже списанного старого экземпляра, обстоятельства и номер заменяющей книги записываются в обосновании. Отдельного акта замены и автоматической проводки КСУ нет.
- Поиск ISBN читает библиографические записи и ограничивает выдачу 50 изданиями; для значительно большего каталога нужен индекс нормализованных ISBN.
- История старых выдач MARCSQL не импортируется: модуль ведёт новые операции. Ранее импортированные экземпляры и читатели используются как есть.
- Обходной лист не реализован. Личный доступ читателей требует создания и связи локальных учётных записей.

Покрыты корзина и откат, повтор запросов, блокировки, права, ISBN, сроки, возврат, штраф, повреждение и утрата, бронь/готовность/истечение, собственные книги, события и уведомления. PostgreSQL-проверки запускают параллельные выдачи одного экземпляра, разных книг одному читателю с лимитом, одинаковые запросы и конкурирующие возврат/продление.
